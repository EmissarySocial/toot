# toot — Notes for AI Agents

Toot is a catalog of the Mastodon REST API for Go servers: the generic `API` struct in [api.go](api.go) holds one handler field per endpoint, and the [route](route/), [scope](scope/), and [txn](txn/) packages hold each endpoint's path, required OAuth scope, and input struct. See [README.md](README.md) for the full picture. Router adapters (currently [toot-echo](https://github.com/benpate/toot-echo)) wire the four together.

- **Every endpoint is declared four times under ONE name, and the compiler cannot cross-check them.** The handler field on `API`, the path constant in `route`, the scope constant in `scope`, and the input struct in `txn` must all carry the identical name (e.g. `PostAccount_Follow`). A typo in any one still compiles — it just creates a constant nothing uses, which silently unbinds that endpoint in every adapter. [consistency_test.go](consistency_test.go) parses all four packages with go/ast and fails on any mismatch; run `go test .` after touching any of them, and add all four declarations together when adding an endpoint.
- **The `<Verb><Entity>_<Subresource>` underscore naming is important — never "fix" it.** One name maps one Mastodon endpoint across four packages and every adapter and consumer. This is why [revive.toml](revive.toml) omits the var-naming rule, and why that file must enumerate revive's entire default rule set explicitly: naming even one rule in a revive config replaces the defaults instead of adding to them.
- **Per-endpoint scope constants must alias the vocabulary constants in [scope/scope.go](scope/scope.go), never bare string literals.** `const PostAccount = WriteAccounts`, not `"write:accounts"` — a literal can drift from the vocabulary unnoticed, and `TestConsistency_ScopeValuesAreNamedConstants` fails on it. `scope.Public` (`""`, no token needed) and `scope.Private` (`"*"`, token needed but no specific scope) are library conventions, not Mastodon scopes; adapters branch on them, so their values are part of the adapter contract.
- **Server code writes pagination with `PageInfo.SetHeader(header, path)`, never `SetHeaders(*http.Response)`.** `SetHeaders` reads `response.Request`, which is only populated for a client following a redirect — on the server side it is nil and the call silently does nothing. `SetHeader` also joins prev/next into ONE comma-separated RFC 8288 `Link` field; writing them with `Header.Set` per link would leave only the last one standing.
- **The [object](object/) types are data carriers only.** JSON tags mirror the Mastodon wire format exactly; they hold no behavior and validate nothing. Validation and authorization are the consuming application's job.
- **The empty admin, push, and streaming files in route/scope/txn are deliberate placeholders.** Those parts of the Mastodon API are not defined yet (no `API` fields either), and the consistency test tolerates the empty files because they declare no names. Don't delete them, and don't add constants to one side without adding all four.
- **`API` is generic over an app-defined `AuthToken` that implements `ScopesGetter`, and `Authorize` must be set.** Adapters call `api.Authorize(request)` to mint the token and `token.Scopes()` to check the endpoint's scope; a nil `Authorize` panics on the first non-public request.

## Every endpoint is declared FOUR times, and nothing ties the names together

An endpoint needs a handler field on `toot.API`, a path in `route`, a required scope in `scope`, and an input struct in `txn`. The four are matched by convention only, so a typo in any one compiles cleanly and silently disables or mis-scopes that endpoint — four had drifted before anyone noticed, including a misspelling that broke Mastodon signup. When adding or renaming an endpoint, change all four together and check the scope constant actually corresponds to the route it guards; a route guarded by the wrong scope is the failure mode that looks like it works.
